Chapter 23 · Tooling

统计学工具链：从数据到可复现报告

会算一个公式不等于能做出一份可靠的分析。真正决定结论能否被复核的，往往是那些不起眼的选择：用哪个库、锁不锁版本、脚本怎么组织、报告能不能一键重跑。

贯穿案例：同一位同事换了台电脑、重跑你的分析脚本，得到的 p 值在小数点后第二位就对不上了。问题最可能出在哪里？

01 · 一条可复现的分析流水线

统计分析的“工具链”不是某个软件，而是一条从问题到结论的流水线。每个环节都会产生中间产物（数据、图表、模型参数）；只有当这些环节能被脚本自动串起来、一步步重跑，结论才可被复核。

顺序也有讲究：先定义问题，再决定需要哪些数据与检验；先看数据，再选模型。反过来“先跑一个能出显著性结果的检验，再回去编故事”，正是第 15 章说的 HARKing。

02 · Python 与 R：按任务分工

“学 Python 还是 R”其实是个假问题。两者都行，差别在生态与工作重心的不同。把任务摊开看，更容易判断：

常见任务的两种实现

描述统计pandas, scipy.statspsych, summarytools
假设检验scipy.statsstats（t.test 等）
回归/方差分析statsmodelslm, glm, aov, car

粗略的建议：以工程落地、机器学习上线为主，Python 更顺；以统计推断、出版级图形与学术写作为主，R 更顺。两者可通过 Quarto 或 rpy2 混用，不必二选一。真正要紧的不是选哪个，而是不管选哪个，都要把流水线写成可重跑的脚本。

03 · scipy.stats：分布与检验

scipy.stats 把常见分布与检验收在一处。做两样本均值比较时，若不确定方差是否齐，默认用 Welch 的 t 统计量：

t=x¯1−x¯2s12n1+s22n2
式 1
import numpy as np
import scipy.stats as stats

rng = np.random.default_rng(42)
group_a = rng.normal(5.2, 1.5, 200)
group_b = rng.normal(6.8, 1.7, 180)

print("A均值/标准差:", round(group_a.mean(),3), round(group_a.std(ddof=1),3))
print("B均值/标准差:", round(group_b.mean(),3), round(group_b.std(ddof=1),3))

print("Shapiro A:", round(stats.shapiro(group_a).pvalue,3))
print("Levene   :", round(stats.levene(group_a, group_b).pvalue,3))

# equal_var=False 即 Welch t 检验（应作为默认选择）
t, p = stats.ttest_ind(group_a, group_b, equal_var=False)
print("Welch t:", round(t,3), round(p,5))

u, up = stats.mannwhitneyu(group_a, group_b, alternative="two-sided")
print("Mann-Whitney U:", round(u,1), round(up,5))

先检查前提，再选检验

上图代码的顺序就是标准流程：描述统计 → 正态性/方差齐性检查 → 选检验（参数或非参数）→ 报效应量。不要先看哪个 p 值小再挑检验——那是数据驱动的“挑好看的”。

04 · statsmodels：建模与诊断

statsmodels 提供接近 R 的公式接口（y ~ x1 + x2），并侧重统计推断而非纯预测。拟合优度常用决定系数：

R2=1−SSresSStot
式 2
import numpy as np
import pandas as pd
import statsmodels.api as sm
import statsmodels.formula.api as smf
from statsmodels.stats.anova import anova_lm

rng = np.random.default_rng(123)
n = 500
X = rng.normal(size=(n, 3))
y = 5.0 + X @ np.array([2.5, -1.3, 0.8]) + rng.normal(scale=1.2, size=n)
df = pd.DataFrame(X, columns=["age", "income", "education"])
df["target"] = y

result = smf.ols("target ~ age + income + education", data=df).fit()
print(result.summary())          # 系数、标准误、t、p、置信区间、R²
print(anova_lm(result))          # 方差分析表
print("Durbin-Watson:", round(sm.stats.durbin_watson(result.resid), 3))
bp = sm.stats.het_breuschpagan(result.resid, result.model.exog)
print("Breusch-Pagan p:", round(bp[1], 4))

summary() 同时给出系数标准误、t 值、p 值与置信区间；anova_lm 给出方差分解。残差自相关（Durbin–Watson）与异方差（Breusch–Pagan）诊断，都是判断模型假设是否成立的常规步骤。

05 · 效应量与区间比 p 值更重要

有了工具，很容易只盯着 p 值。但 p 值同时受效应大小与样本量影响；大样本下微不足道的差异也能“显著”。衡量差异本身的是效应量，例如两组的 Cohen's d：

d=x¯1−x¯2sp

其中 sp 是合并标准差。Cohen 提出的粗略参照是 d ≈ 0.2 小、0.5 中、0.8 大，但这些基准与领域强相关，不能当硬标准：

失败模式：只报 p 值

“p < 0.001，所以效应很大”是常见误读。p 小只说明“难用随机波动解释”，不代表差异在实务上重要。报告应同时给出效应量与其置信区间。

06 · 环境与项目结构

工具链里的另一半是环境管理和项目结构。它们不产生结果，却决定了结果能不能在别处重现。一个常见的推荐结构是：

project/
  data/raw/          # 原始数据，只读
  data/processed/    # 清洗后的数据
  notebooks/         # 探索性分析
  src/               # 可复用的函数
  output/            # 图表与表格
  reports/           # 最终报告
  requirements.txt   # 依赖与版本

把“原始数据只读、所有变换由脚本完成”作为习惯，能避免“改了一个数但不知道谁改的”。在 Python 项目中用 requirements.txt 或 environment.yml 锁定版本；在 R 项目中用 renv。

失败模式：不锁版本，结果“飘了”

同一份脚本，在两个不同机器上因库版本或随机种子不同，可能得到不同结果。随机数必须显式设种子；关键结论最好在不同环境或另一套工具里互相验证。以下是一个合成示例（仅说明道理，不是具体版本的事实）：两分析师的 numpy 版本不同，随机数生成器实现不同，在同一段“无种子”代码上会生成不同样本，p 值自然就不同。

本章开头的问题“换台电脑结果就对不上”，最常见的三个原因是：没固定随机种子、没锁库版本、手改了没写进脚本的数据。逐项排除即可。

07 · 自我检查与可复现计算

把前文的例子上手算一遍 Cohen's d：两组样本量 200 与 180，均值 5.2 与 6.8，标准差 1.5 与 1.7。先算合并方差，再算 d。

import math

n1, n2 = 200, 180
mean1, mean2 = 5.2, 6.8
s1, s2 = 1.5, 1.7

sp2 = ((n1-1)*s1**2 + (n2-1)*s2**2) / (n1+n2-2)
sp = math.sqrt(sp2)
d = (mean1 - mean2) / sp
print("合并方差 sp2 =", round(sp2, 4))   # 约 2.5526
print("合并标准差 sp =", round(sp, 4))  # 约 1.5977
print("Cohen's d     =", round(d, 3))   # 约 -1.001（绝对值约 1.0）

自我检查

问题：一个 t 检验给出 p = 0.0001，能否直接说“效应很大”？

参考答案：不能。p 同时受效应量与样本量影响。应报告效应量（如 Cohen's d）及其置信区间；大样本下很小的效应也能得到极小的 p。

自我检查二：工具链的两条底线

问题：如果只能保留两条关于工具链的习惯，哪两条最重要？

参考答案：一、所有分析用脚本重跑，中间产物落盘；二、固定随机种子并锁定依赖版本。做不到这两条，再高级的库也无法保证结果可重现。
